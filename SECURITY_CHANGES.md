## Что изменено

- API, файлы и Socket.io принимают только JWT с `type: access`, действующим сроком и активным пользователем в БД. Приглашение и сброс пароля не дают API-доступа. Для проверки подписи явно разрешён HS256.
- Приглашения используются однократно. Ссылка сброса привязана к текущему паролю через HMAC и перестаёт действовать после смены пароля. Конкурирующие попытки изменения пароля/активации проверяются атомарным условным обновлением.
- Веб-вход (`client: web`) и обновление через cookie возвращают только пользователя. JWT и refresh-токен хранятся в httpOnly cookies. Старые копии из localStorage удаляются; фотографии, скачивание экспорта и чаты в браузере используют cookie.
- Для мобильного клиента сохранены Bearer-запросы и refresh-токен в SecureStore. Query-токен разрешён только на GET файлов и экспорта для совместимости с текущей мобильной версией. Токен больше не добавляется к внешним URL. В access-логах nginx исключены query-параметры.
- CSRF: подписанная cookie, обязательный заголовок для операций с cookie-сессией, включая refresh/logout, проверка Origin. Отдельный GET /api/auth/csrf позволяет клиенту подготовить защищённый запрос.
- Глобально подключён HTTP ThrottlerGuard: 300 запросов в минуту на IP/маршрут; более строгие лимиты login, forgot, upload, batch и export используют существующие декораторы. Login/forgot дополнительно разделяются по нормализованному email, чтобы сотрудники за одним маршрутизатором не блокировали друг друга. Для прокси используется req.ip, а не сырой X-Forwarded-For. В Compose явно задан TRUST_PROXY для внутренней сети; при прямом запуске доверие к прокси по умолчанию выключено.
- Файлы проверяются по текущим связям: ребёнок, видимость наблюдения/заметки, группа, участники чата, опубликованная статья, событие и общедоступный контент. Черновик доступен загрузившему его пользователю; администраторы сохраняют предусмотренный полный доступ. Неизвестный файл без разрешающей связи закрыт, в том числе при отсутствии FileMeta.
- Старые абсолютные URL поддерживаются, превью наследуют права оригинала. Запись в профиль/чат/публикацию не позволяет присвоить чужой закрытый файл: вложения проверяются перед сохранением. Прямые Socket.io-сообщения проходят такую же проверку.
- Заблокированный пользователь не может читать файлы или отправлять/получать новые сообщения в чате. Соединение закрывается при истечении JWT; клиенты обновляют сессию при переподключении.
- SVG при новой загрузке преобразуются в растровое изображение; расширения документов выбираются по проверенному MIME. Ответы файлов запрещают выполнение активного содержимого и кеширование приватных данных. Публичные брендовые изображения также получают ограничительную CSP.
- Родительский экспорт исключает скрытые наблюдения. Исправлен адрес экспорта в вебе и передача адреса WebSocket в Docker-сборку.

Сквозные тесты используют настоящую PostgreSQL, HTTP, cookie и Socket.io. Отправка почты и чтение объектов S3 подменены тестовыми реализациями. Нужны зависимости backend и web (Socket.io-клиент берётся из web).

**Использовать только отдельную локальную базу `globoatlas_security`: тесты очищают её таблицы.** Подключение через основной DATABASE_URL не используется. Сначала применить миграции к этой тестовой базе, затем:

```sh
SECURITY_TEST_DATABASE_URL=postgresql://USER@127.0.0.1:PORT/globoatlas_security npm run test:e2e -- --runInBand
```

Также восстановлены пропущенные записи нативных пакетов Sharp/SWC в lock-файлах; версии существующих пакетов сохранены. Чистая установка на Mac выполняется через `npm ci --include=optional`.

## Выпуск и границы проверки

- Обновлять backend и web согласованно. Текущий мобильный клиент может обновить старый access-токен через refresh; при отсутствии действующего refresh потребуется повторный вход.
- Ранее выданные ссылки сброса пароля нужно запросить заново. Ссылки приглашения остаются действующими только для ещё не активированных аккаунтов.
- Файлы, не связанные ни с одной доступной записью и не принадлежащие пользователю, намеренно закрыты. При проверке старых данных восстанавливать корректные связи, а не разрешать доступ всем.
- Браузерный портал и API должны работать на одном сайте; CORS_ORIGINS и PUBLIC_APP_URL должны содержать реальные адреса. При отдельном прокси TRUST_PROXY должен перечислять только доверенную инфраструктуру.
- Лимитер сейчас хранит счётчики в памяти одного backend-процесса. Перед несколькими репликами требуется общее хранилище счётчиков. Чтение связей файлов выполняется непосредственно по БД; при росте объёма медиа нужен индекс ссылок с сохранением текущих правил доступа.
- Это исправление обнаруженных проблем, не полный аудит: отдельной проверки требуют остальные бизнес-права/DTO, инфраструктура, зависимости и резервное восстановление. Native UI и реальный S3 в сквозных тестах не проверяются. Query-токены старой мобильной версии остаются временной совместимостью; последующий переход на загрузку через заголовки/ограниченные одноразовые ссылки позволит полностью убрать их.
