# Директор, отметки работы и путь семьи из Tilda

Код обновления подготовлен 15 сентября 2026. Публикация в GitHub сама по себе не обновляет VPS. Требуются согласованные backend/web, миграции до `20260916030000_admission_document_checklist` включительно и перезапуск nginx. Существующие аккаунты, пароли и записи сохраняются; тестовые пользователи автоматически не создаются. Карточка и документы ребенка: [CHILD_PROFILE.md](CHILD_PROFILE.md).

## Директор

Войдите суперадминистратором → «Сотрудники» → «Пригласить сотрудника», выберите «Директор». Можно также изменить роль существующего сотрудника. После смены роли сотруднику следует выйти и войти заново, чтобы обновилось меню.

Директор управляет детьми, группами, родителями, посещаемостью, обычными сотрудниками, отчетами, табелем, календарем, материалами и CRM, включая ее этапы. Он не может менять собственную роль, управлять другим директором или суперадминистратором, назначать директоров, менять системные настройки и пользоваться функциями, оставленными только владельцу. Эти ограничения проверяет backend.

## «Начал работу / Завершил работу»

В `.env` на VPS настройте:

```dotenv
TEAM_CLOCK_ENABLED=true
TEAM_WORKPLACE_CIDRS=ВНЕШНИЙ_СТАТИЧЕСКИЙ_IP_САДА
TEAM_TIMEZONE=Europe/Moscow
```

Замените заглушку реальным внешним IP интернет-подключения сада. Это не IP VPS и не локальный адрес 192.168.x.x. При нескольких подключениях перечислите адреса через запятую. Поддерживаются IPv4, IPv6 и CIDR; пустая или некорректная настройка запрещает отметки. Широкие сети использовать не следует. При динамическом IP сначала согласуйте статический адрес с провайдером.

После изменения `.env` пересоздайте backend и nginx с production Compose. Одного `restart backend` недостаточно для применения переменных окружения. В примере ниже `dcp` — функция из раздела обновления:

```bash
dcp up -d --force-recreate --no-deps --wait --wait-timeout 180 backend
dcp up -d --force-recreate --no-deps --wait --wait-timeout 60 nginx
```

Сотрудник открывает «Команда → Табель» со своего аккаунта. Обе кнопки доступны только из разрешенной сети. Время задает сервер; часы считаются по закрытым интервалам с вычетом заданного руководителем перерыва один раз за день. Несколько интервалов суммируются. Ночная смена относится к дате ее начала в настроенном часовом поясе. Открытая смена еще не добавляет фактические часы в итог.

При этом режиме сотрудник не вводит факт вручную. Руководитель задает график, видит журнал отметок и IP, при забытом окончании закрывает смену с фактическим временем и причиной. Смену длиннее суток сотрудник сам закрыть не может: руководитель должен уточнить время. Ручное исправление часов требует причины, исходные отметки сохраняются. Исправленный вручную итог не перезаписывается новой сменой. Утвердить месяц с открытой сменой нельзя.

Проверка подтверждает выход через сеть сада. Она не является доказательством физического присутствия, если сотрудник может подключаться к этой сети удаленно через VPN. Текущая схема рассчитана на прямой доступ к единственному nginx VPS: он заменяет входящий X-Forwarded-For, backend не опубликован наружу. При добавлении CDN или другого прокси нужно отдельно настроить доверенные адреса; нельзя просто доверять присланному клиентом IP.

Если оставить `TEAM_CLOCK_ENABLED=false`, сохраняется прежний ручной табель. Уже созданные отметки не удаляются, дни с ними сотрудник вручную не переписывает. При выключении режима незавершенную смену закрывает руководитель. Новые экраны доступны в веб-портале, в том числе с телефона.

## Подключение Tilda

1. Создайте случайный секрет на VPS командой `openssl rand -hex 32`. Сохраните его в `.env` как `TILDA_WEBHOOK_TOKEN=...`. Не публикуйте его в GitHub, коде страницы или переписке. Это отдельный секрет, не JWT_SECRET и не CRM_WEBHOOK_TOKEN.
2. Убедитесь, что `CRM_ENABLED=true`, и пересоздайте backend и nginx командами выше.
3. В Tilda: **Настройки сайта → Формы → Webhook**. Адрес: `https://lk.globokids.ru/api/crm/tilda`.
4. В дополнительных настройках API-ключа выберите передачу **в заголовках / HEADERS**. Имя: `Authorization`. Значение: `Bearer ` и ваш секрет после пробела. Передачу ключа в POST-поле этот обработчик не принимает.
5. Сохраните подключение. Tilda отправит `test=test`, портал должен ответить HTTP 200 и `ok`.
6. В «Контенте» каждого блока формы отметьте подключенный Webhook и заново опубликуйте страницу.

Поддержка стандартных полей текущего сайта (`messenger-type`, `messenger-id`, `Input`, `Date`, `Checkbox`, `Checkbox_2`) и правила сопоставления: [CRM_ENROLLMENT_UPDATE.md](CRM_ENROLLMENT_UPDATE.md).

Рекомендуемые явные названия переменных для новых форм:

| Переменная в Tilda | Куда попадет | Обязательность |
| --- | --- | --- |
| `Name` или `parentName` | Имя родителя | Обязательно |
| `Phone` | Телефон родителя | Обязательно для связи по телефону; в мессенджере вместо него допускается `contactValue` |
| `Email` | Email родителя | Можно заполнить перед зачислением |
| `childName` | Имя ребенка | Можно заполнить в CRM |
| `birthDate` | Дата рождения | Необязательно, формат YYYY-MM-DD |
| `direction` | Интересующее направление | Необязательно |
| `Comments` или `notes` | Комментарий | Необязательно |
| `childAge` | Возраст ребенка, например «2 года 8 месяцев» | Необязательно; не заменяет дату рождения |
| `contactMethod` | Предпочтительный способ связи | `phone`, `telegram`, `vk`, `max`; без поля используется `phone` |
| `contactValue` | Ник, ссылка на профиль или телефон | Для выбранного способа связи; если пусто, берется `Phone` |
| `visitDate` | Желаемая дата посещения | Сохраняется как ответ формы, без автоматического назначения встречи |
| `dataConsent` | Ответ о согласии на обработку данных | Отдельная переменная первого чекбокса |
| `marketingConsent` | Ответ о рекламных сообщениях | Отдельная переменная второго чекбокса |

Подписи полей на странице можно оставить как на макете. Настраиваются именно имена переменных в «Контенте» формы. Кнопки выбора мессенджера отправляют `contactMethod` или стандартное `messenger-type`, а поле с ником/телефоном — `contactValue`, `messenger-id` или `Phone`. Стандартное значение `max_messenger` распознается как Max. Если это собственный HTML-виджет, проверьте, что эти поля входят в отправляемую форму: внешний вид кнопок сам по себе не задает данные Webhook.

Ответы двух чекбоксов хранятся отдельно: `yes/true/1/on/да` — отмечено, `no/false/0/off/нет` — не отмечено. Пустое или отсутствующее поле отображается как «Сведения не переданы»; другое значение сохраняется дословно без предположения о согласии. Для однозначной передачи используйте yes/no. Эти ответы не активируют аккаунт родителя и не запускают рассылку.

У заявки из мессенджера телефон может быть пустым: контакт и возраст видны на доске/в карточке, исходные ответы формы сохраняются отдельно от редактируемых заметок. Телефон добавляется через «Изменить» или прямо в окне зачисления. Введенный возраст не пересчитывается в выдуманную дату рождения, а желаемое посещение не подставляется как начало обучения. Для нескольких заявок без телефона подсказка о совпадении пустого телефона не создается. Ник доступен в поиске CRM.

Регистр имен переменных не важен. `tranid` добавляет Tilda, вручную создавать это поле не нужно. При необходимости UTM передаются отдельными полями `utm_source`, `utm_medium`, `utm_campaign` или через TILDAUTM в COOKIES. Сырые cookies и неизвестные поля не сохраняются. Направление — текст заявки; отдельного справочника «продукты» в текущей версии нет.

Повтор одного `tranid` создает только одну заявку, в том числе при одновременной повторной доставке. Разные отправки с одним телефоном сохраняются отдельно: это может быть другой ребенок. В карточке показываются связанные заявки с тем же нормализованным телефоном. Портал возвращает Tilda только `ok`, без данных семьи и внутренних идентификаторов. Форма Tilda должна иметь собственную защиту от спама.

Если подключение не сохраняется, проверьте журнал ошибок форм Tilda, точный HTTPS-адрес, способ передачи ключа HEADERS, пробел после Bearer и пересоздание backend после изменения `.env`. Если `test=test` прошел, но заявки нет, проверьте привязку Webhook к конкретному блоку, повторную публикацию и имена полей. Несовпадение обязательных полей дает HTTP 400; неверный секрет — 401; отключенная CRM — 404.

Основание формата и настроек: [официальная инструкция Tilda](https://help-ru.tilda.cc/forms/webhook). Tilda ожидает ответ за пять секунд и повторяет неудачную доставку; стабильность реального подключения проверяется отправкой опубликованной формы.

## Проверка пути семьи

Используйте отдельный тестовый email, который контролируете, и вымышленные данные ребенка. Отправка приглашения выполняется только по отдельной кнопке.

1. Отправьте опубликованную форму Tilda. В CRM должна появиться заявка с источником «Tilda» и телефоном в формате +7….
2. Откройте ее, назначьте ответственного, пройдите этапы «Общение», «Экскурсия», «Встреча», «Оформление». Можно записывать результаты контактов и назначать следующий контакт.
3. Нажмите «Зачислить». Форма перечислит недостающие данные: имя и дата рождения ребенка, родитель, телефон, email или существующий родитель, группа, начало посещения. Проверяется допустимость дат, доступность аккаунта и свободное место. При совпадении существующего ребенка нужно явно выбрать его.
4. Дополните сведения и чек-лист документов. Для зачисления с недостающими обязательными документами нужен комментарий администрации (от 10 символов). Чек-лист можно сохранить заранее; его снимок останется в папке ребенка. Подтвердите зачисление. Сервер повторно проверяет условия зачисления. Ребенок появится в выбранной группе основного портала с началом посещения, стоимостью и адаптацией; заявка перейдет в «Зачислены». Фото, представителей и дополнительные сведения можно дополнить в карточке ребенка.
5. В зачисленной заявке нажмите «Отправить приглашение родителю». Нужны рабочие SMTP-настройки Яндекса и `PUBLIC_APP_URL=https://lk.globokids.ru`. Ошибка отправки не отменяет зачисление; после исправления почты отправку можно повторить.
6. Откройте письмо в отдельном профиле браузера или инкогнито, перейдите по ссылке, примите условия и задайте пароль. Затем войдите родителем: должен быть виден именно его ребенок. Если родитель уже активировал аккаунт, его прежний пароль сохраняется, новое приглашение не отправляется.

Зачисление само по себе не отправляет пароль по почте. Ссылка приглашения позволяет родителю создать пароль, действует 30 дней и перестает приниматься после активации аккаунта. Доставка реального письма и доступность внешнего видео зависят от соответствующих сервисов и требуют отдельной проверки.

## Видеоуроки методиста

«Правила и материалы» → создать материал → тип «Пособие» → название и описание → поле ссылок: вставить URL VK Видео или Rutube, по одному на строку → аудитория «Педагоги» или «Все сотрудники» → опубликовать.

Для правил сада выбирайте «Все пользователи» — это авторизованные пользователи, включая родителей. Для учебного плана — «Педагоги». Ссылки открывают видеосервис в отдельной вкладке. Доступность самого ролика определяется настройками VK/Rutube: скрытая в портале ссылка не делает публичный ролик закрытым.

## АТС и повторы

В этом обновлении адаптер АТС не подключен. Для Билайн требуется подтвердить именно используемую услугу и получить документацию API из ее личного кабинета: официальный сайт [Облачной АТС Билайн](https://moskva.beeline.ru/business/telephony/cloud-ats/) указывает интеграцию собственной CRM через API. Пароли и токены не нужны в чате; потребуются описание методов/событий и обезличенный пример события звонка.

Правила будущего коннектора: уникальный ID звонка защищает от повторных событий; телефон нормализуется так же, как в Tilda; при одной подходящей открытой заявке звонок и запись прикрепляются к ней. Если заявок несколько, связь требует выбора — нельзя автоматически объединять детей по номеру родителя. Новый лид создается только при отсутствии подходящего контакта. Одновременные события и завершенные заявки требуют явной политики сопоставления. Записи должны открываться только авторизованным сотрудникам, без публикации ключей АТС и постоянных общедоступных URL.

## Обновление VPS

Выполните в согласованное время: после сборки будет короткий перерыв. Не запускайте `migrate reset`, не удаляйте Docker volumes. Если `git pull --ff-only` сообщает о локальных изменениях или конфликте, остановитесь и разберите их; не используйте `reset --hard`.

```bash
cd /opt/globoatlas
dcp() { docker compose -f docker-compose.yml -f docker-compose.prod.yml "$@"; }
git pull --ff-only origin master
dcp config --quiet
dcp build backend
dcp build web
```

После успешной сборки обоих образов выполните одним блоком:

```bash
bash <<'UPDATE'
set -euo pipefail
cd /opt/globoatlas
dcp() { docker compose -f docker-compose.yml -f docker-compose.prod.yml "$@"; }
umask 077
release_backup="/opt/globoatlas-backups/update-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$release_backup"
cp .env "$release_backup/env"
dcp stop backend web
dcp exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' </dev/null > "$release_backup/database.dump"
test -s "$release_backup/database.dump"
dcp exec -T postgres pg_restore --list < "$release_backup/database.dump" >/dev/null
dcp run --rm -T --no-deps backend npx --no-install prisma migrate deploy </dev/null
dcp up -d --wait --wait-timeout 240 backend web
dcp up -d --force-recreate --no-deps --wait --wait-timeout 60 nginx
dcp exec -T nginx nginx -t </dev/null
dcp ps
printf 'Обновление запущено. Резервная копия: %s\n' "$release_backup"
UPDATE
```

При ошибке блок останавливается. Сохраните вывод ошибки; не повторяйте миграции с `reset`. Архив выше защищает базу перед этой миграцией, но не заменяет регулярную копию файлов хранилища и проверку восстановления. Если нужны новые переменные Tilda/табеля, заполните их перед запуском обновления либо затем пересоздайте backend/nginx. После входа проверьте тестовую семью по сценарию выше, затем отметки из Wi-Fi сада и через мобильный интернет.

## Проверки этого изменения

41 модульный тест backend и 4 теста веб-сессий прошли. Проверены права директора, запрет IP, формат Tilda и список недостающих сведений; сборка backend и проверка типов backend/web/mobile успешны. Добавлены сквозные сценарии PostgreSQL для директора, отметок и всей цепочки Tilda → зачисление → приглашение → вход родителя. Запуск отдельной локальной PostgreSQL не был разрешен, поэтому новая миграция и эти сценарии еще не проверены выполнением. Производственная база и аккаунты внешних сервисов в ходе разработки не изменялись.

Дополнение для расширенной формы: новая миграция `20260916010000_tilda_form_details` добавляет необязательные исходные сведения Tilda. Старые заявки сохраняются; ранее проигнорированные поля автоматически не восстанавливаются. После обновления отправьте новую тестовую форму. Тело Webhook, включая сырые cookies и неизвестные поля, не сохраняется в журнале аудита; фиксируется результат запроса. Проверки с реальными Tilda/PostgreSQL выполняются отдельно после развертывания.

Для дополнения формы прошли 12 целевых модульных тестов (Tilda, CRM без телефона, журнал аудита), сборка backend и проверка типов web. Новая миграция PostgreSQL и доставка реальной формы еще требуют проверки на сервере.
