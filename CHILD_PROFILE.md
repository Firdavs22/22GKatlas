# Карточка ребенка и документы

Обновление от 16 сентября 2026 года. Требуется миграция `20260916020000_child_profile_documents` (двенадцатая). Она добавляет поля и таблицу документов, сохраняя существующие записи. Значение разрешения на публикацию у старых карточек — «Не уточнено». Новые переменные `.env` не нужны.

## Как пользоваться

- Администрация: **Дети → ребенок → Редактировать**. В контактах есть кнопки «Мама», «Папа», «Родственник», «Няня», «Водитель»; для каждого можно указать имя, телефон, почту. Можно добавить несколько родственников и произвольные роли. Существующие контакты сохраняются. Роль мамы/папы не угадывается по имени привязанного аккаунта — ее нужно указать.
- «Кто может забирать» заполняется отдельно: контакт няни или водителя сам по себе не означает разрешения забирать ребенка и не создает аккаунт в портале.
- Ниже находятся **Питание, почта и публикации**. Запрещенные продукты и явный запрет публикации выделены красным и подписаны текстом. Аллергии остаются отдельным полем. Для публикаций доступны «Не уточнено», «Разрешено», «Запрещено» и комментарий; изменения сохраняются отдельной кнопкой. При конфликте правок нужно обновить страницу и сверить сведения.
- Почта для связи не меняет адрес входа или получателя приглашения. Аккаунт и приглашение настраиваются в разделе «Родители».
- Родители: **Карточка ребенка** в меню. При нескольких детях доступен выбор. Родители читают сведения, загружают и скачивают документы; ограничения изменяет администрация.
- Педагог: **Дети группы → Карточка ребенка и ограничения**. Контакты, питание и публикации доступны для просмотра; документы не показываются и закрыты на сервере.

Разрешение на публикацию не выводится из согласий на рекламу или обработку данных в Tilda. Отметка и приложенный документ фиксируют сведения для сотрудников; это не система автоматической блокировки публикаций в социальных сетях.

## Папка документов

Разделы: договоры, медицинские документы, согласия, прочее. Форматы: PDF, DOC, DOCX, XLSX, JPG, PNG, WEBP; один файл до 20 МБ. Проверяется тип содержимого, файлы сохраняются в исходном качестве в приватном хранилище.

Список и файлы доступны только `admin`, `director`, `superadmin` и аккаунтам `parent`, связанным с этим ребенком. Педагог, методист, психолог, педиатр и чужие родители не имеют доступа, в том числе по прямой ссылке. Проверка учитывает текущую связь родителя с ребенком. Копирование ссылки в чат или общую публикацию не расширяет права на файл.

Администрация может убрать любой документ из папки; родитель — только загруженный им. Это мягкое удаление: запись и файл сохраняются, родителям файл становится недоступен. Административный доступ к хранилищу сохраняется. Старое поле `Child.documents` с отметками наличия документов остается без изменений; реальные файлы нужно загрузить в новую папку.

## Проверки

Пройдены production-сборки backend/web, проверка типов web, 62 модульных теста backend и 11 дополнительных проверок документов/загрузок: права файлов и папки, запрет чужих документов, сохранение оригинала скана, кириллические имена файлов, проверка MIME, ограничение размера, удаление и конфликт правок разрешений. В системных текстах интерфейса, писем, отчетов, мобильного приложения и документации используется буква е. Введенные пользователями имена и тексты в базе не переписываются; примененные миграции не изменяются. Команды:

```bash
cd backend
npx --no-install prisma generate
npm run build
npm test -- --runInBand --watch=false
node --test test/child-documents.test.cjs test/uploads.test.cjs
cd ../web
./node_modules/.bin/tsc --noEmit --incremental false
npm run build
```

Новая миграция и загрузка через настоящий PostgreSQL/SeaweedFS локально не выполнялись. После обновления VPS проверить на тестовом ребенке: заполнение всех контактов, сохранение запрета и комментария после перезагрузки, загрузку/скачивание PDF из кабинетов администрации и связанного родителя, отказ чужому родителю и педагогу по той же ссылке. Затем убрать тестовый файл из папки и проверить отказ родителю.

## Обновление VPS

Выполнить блок целиком в SSH. Сборка идет при работающем портале; после нее будет короткий перерыв на резервную копию, миграцию и перезапуск. `.env` сохраняется. При ошибке выполнение останавливается — сохранить вывод для диагностики.

```bash
bash <<'UPDATE'
set -euo pipefail
cd /opt/globoatlas
dcp() { docker compose -f docker-compose.yml -f docker-compose.prod.yml "$@"; }
git pull --ff-only origin master
dcp config --quiet
dcp build backend
dcp build web
umask 077
release_backup="/opt/globoatlas-backups/update-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$release_backup"
cp .env "$release_backup/env"
dcp stop backend web
dcp exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' </dev/null > "$release_backup/database.dump"
test -s "$release_backup/database.dump"
dcp exec -T postgres pg_restore --list < "$release_backup/database.dump" >/dev/null
dcp run --rm -T --no-deps backend npx --no-install prisma migrate deploy </dev/null
dcp up -d --wait --wait-timeout 240 backend web
dcp up -d --force-recreate --no-deps --wait --wait-timeout 120 nginx
dcp exec -T nginx nginx -t </dev/null
dcp ps
printf '\nОбновление завершено. Резервная копия: %s\n' "$release_backup"
UPDATE
```

Копия выше содержит базу и `.env`, но не файлы SeaweedFS. Регулярное резервное копирование хранилища необходимо отдельно. Не удалять Docker volumes, не запускать `migrate reset`, не создавать первого администратора заново.
