# Кабинет педагога: публикации, табель, материалы и календарь

## Обновление VPS

```bash
cd /opt/globoatlas &&
git pull --ff-only origin master &&
bash scripts/update-production.sh
```

Скрипт собирает backend и web, сохраняет базу и `.env`, применяет миграции и запускает
контейнеры. Новая миграция `20260918000000_library_review` добавляет состояние проверки
материалов. Уже существующие материалы и их видимость сохраняются. Нужна обычная
пересборка: одного `git pull` для этих изменений недостаточно.

## Публикация наблюдения

Исправлено несоответствие формы серверной проверке: сервер принимает `title`, `photos`,
`visible`, `areaId`, `tags`. Ограничения размера текста и числа вложений, проверка доступа
к ребенку и файлам сохраняются. Ошибки в форме показываются отдельными фразами.
Старые поля `attachments` и `privateToTeacher` также поддерживаются.

Проверка онлайн: педагог → «Дневник» → «Новый пост» → ребенок, текст, фото → публикация.
Видимый родителям пост появится в дневнике ребенка; приватный не должен появляться
у родителя.

## Начало и окончание работы

В «Мой табель» одна кнопка: «Начал работу» → «Завершить работу». Во время смены
видны начало и счетчик. Начало и окончание фиксирует сервер; после завершения
рассчитывается фактическое время с учетом перерыва из табеля. Смена сохраняется
после закрытия страницы. Для проверки с другого устройства статус обновляется
при возвращении на страницу и каждые 30 секунд.

При отключенном учете кнопка видна, но неактивна и поясняет причину. Рабочий IP
по-прежнему проверяется сервером как при начале, так и при окончании смены.

Сначала узнайте адрес **в самом саду**:

1. Подключите телефон или ноутбук к Wi-Fi сада. Отключите VPN, прокси и на телефоне
   мобильный интернет, чтобы запрос точно прошел через сеть сада.
2. В браузере этого устройства откройте [показать внешний IPv4](https://api.ipify.org).
   Страница покажет адрес подключения — скопируйте его. Это сервис
   [ipify](https://www.ipify.org/), определяющий публичный IP запроса.
3. Не открывайте эту страницу из браузера удаленного сервера и не запускайте команду
   определения IP через SSH: так получится адрес VPS, а нужен адрес сада.

Для включения после обновления выполните **на VPS**:

```bash
cd /opt/globoatlas
bash scripts/configure-workplace-clock.sh
```

Скрипт спросит **внешний IP интернета в саду**, изменит только `TEAM_CLOCK_ENABLED`
и `TEAM_WORKPLACE_CIDRS`, сохранит прежний `.env` вне репозитория и пересоздаст backend
и nginx. Пароли и содержимое `.env` не выводятся. Нужен публичный IPv4/IPv6, можно
несколько адресов через запятую. Не вводите IP VPS, `192.168.*` или название Wi-Fi.

Адрес можно узнать у провайдера интернета сада или в настройках роутера (WAN).
Если там локальный адрес, уточните внешний адрес у провайдера. При динамическом IP
после его смены список нужно обновить; для постоянного контроля удобен статический IP.
Учет проверяет выходной IP сети, а не сам факт физического присутствия человека.

## Предложения методисту

Педагог: «Правила и материалы» → «Предложить материал или правило» → текст, файлы
или ссылки → «Отправить на проверку». Статус доступен во вкладке «Мои предложения».

Методист (также директор/суперадминистратор): «На проверке» → «Открыть» → выбрать
аудиторию → «Одобрить и опубликовать» либо «Вернуть на доработку». Для возврата
обязателен комментарий. Педагог может исправить возвращенный материал и отправить
повторно. Уведомления о подаче и результате приходят внутри портала.

До публикации предложение и его вложения видят только автор, методист и руководство.
Другие педагоги, обычный администратор и родители не получают доступ по ссылке.
После одобрения действует выбранная аудитория. Комментарий проверки видят автор
и редакторы. Одновременные решения защищены номером версии материала.

## Карта развития и планирование

Текущий функционал: матрица навыков, стадии «Не начат / Знакомство / Повторение /
Усвоено», история изменений, дневник и рекомендации ребенку. У психолога есть
заметка «План работы». Эти возможности сохранены.

Отдельного индивидуального плана педагога с целями, выбранными навыками, сроками,
ответственными и статусом выполнения сейчас нет. Событие «План работы» в календаре
планирует время, но не создает такой план в карте развития. В этом обновлении
индивидуальные планы и автоматическое планирование с ИИ не добавлялись.

## ИИ и данные ребенка

Генерация описания теперь использует фиксированное направление занятия: сенсорика,
математика, речь, практическая жизнь и т. п. Внешнему провайдеру отправляются только
серверный текст направления и случайный код запроса. Имя, внутренний ID ребенка,
дата рождения, фотографии, документы, заголовки и свободные заметки не отправляются.
Даже если старый клиент передаст свободный текст, сервер не включит его в запрос
к ИИ. ID из новой формы нужен только внутри портала для проверки доступа к ребенку.

Это заготовка общего описания занятия, а не анализ индивидуального развития.
Педагог добавляет наблюдения и проверяет текст перед публикацией. Ответ ИИ
самостоятельно не публикуется и не меняет карту развития. Простая замена имени
на ID не защищает персональные данные, если оставить их в свободном тексте.

При `AI_PROVIDER=stub` работает локальный шаблон. Для внешнего сервиса с уже
поддерживаемым протоколом chat completions нужны настройки в `.env`:

```ini
AI_PROVIDER=openai-compat
AI_API_URL=https://ai-provider.example/v1
AI_MODEL=model-name-from-provider
AI_API_KEY=secret-from-provider
```

Это примеры: адрес, модель и ключ нужно получить у выбранного провайдера и заменить
на настоящие **на VPS**. Ключ не нужно присылать в чат. Для удаленного сервиса
используйте HTTPS. После изменения `.env`:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --no-deps --force-recreate --wait --wait-timeout 180 backend
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --no-deps --force-recreate --wait --wait-timeout 120 nginx
```

Внешний сервис в рамках этой работы не подключался. Если он недоступен, через
ограниченное время ожидания используется локальная заготовка, и форма сообщает об этом.
Тела запросов ИИ не копируются в аудит, ответы об ошибках провайдера не пишутся в лог.

## Календарь и даты

Нажатие на день показывает его события в соседней панели (на телефоне — ниже
календаря) с кнопкой «Добавить событие». Дата выбранного дня подставляется в форму.
Личные события фиолетовые, общие — зеленые. Права видимости не менялись.
Многодневное событие, заканчивающееся в полночь, не занимает следующий день.

Единый выбор даты и месяца с русскими названиями, выбором года и кнопкой «Сегодня»
заменяет прежние поля в календаре, табеле, карточках детей, CRM, расписании приемов,
питании, мероприятиях, оплате и отчетах. Время выбирается отдельно от даты.

## Проверка и диагностика

По договоренности локальные тесты, сборка и запуск приложения не выполнялись.
Проверены исходники и форматирование. После обновления проверить онлайн публикацию
педагогом, начало/окончание смены из рабочей сети, предложение и решение методиста,
доступ родителя к опубликованному материалу, событие на выбранный день.

Если сервер вернул ошибку, сразу на VPS:

```bash
cd /opt/globoatlas
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs --since 10m --tail 100 backend
```

Перед отправкой фрагмента уберите персональные данные и секреты, если они есть.
